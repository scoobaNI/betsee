How it works

One request. One boundary. One answer you can read.

  1. 01

    An agent asks.

    A tool call, a file read, a payment or a message to another agent becomes one small request to the Betsee Gateway, made with the agent's own identity. Never its human's.

  2. 02

    Policy decides.

    Cedar policies, the information tier, budgets and command rules decide first. AI analysis runs after them and may only make the answer stricter.

  3. 03

    You see why.

    Allow, deny, approval or step-up, with the control and policy that decided it. Live in the Director, append-only in the audit trail.

Betsee Desk

Claude Code and Codex for every employee. Governed.

Desk is a desktop app where people work with real Claude Code or Codex. Every tool call the runtime attempts goes to the Gateway as the agent employee-assistant and is decided before it runs.

  • Reads of catalogued files by information tier
  • Writes only after an approver says yes
  • No network egress; denied when the Gateway is unreachable

Content and runtime controls

Sensitive data stops at the boundary.

What people type is checked before the model sees it: card numbers by Luhn, IBANs by mod-97, PESEL by checksum, API and private keys. What the model reaches for is checked against the session's ceiling.

  • CTL-IN-001 keeps secrets and personal data out of the prompt
  • CTL-TIER-001 keeps confidential files above the session ceiling
  • CTL-FILE-001 scans every upload and download by its bytes

Approvals

A human decides. With proof of who they are.

High-impact actions wait for an approver who sees the exact parameters the Gateway stored, not the agent's summary. The approval binds to the hash of that request.

  • The approver must be someone other than the session's human
  • The most sensitive actions need a fresh one-time code
  • Agent-supplied values are shown apart, marked unverified

Policy Studio

Every guarantee is a named control.

Each control says in plain language what it guarantees, which OWASP risks it mitigates and where it attaches: organisation, team, user, agent, use case, tool, model or information tier.

  • Policies are Cedar, validated in strict mode at startup
  • An invalid policy stops the Gateway from starting
  • Any evaluation error is a deny

Identity

Every agent is a principal, not a borrowed login.

Each agent has its own identity and sits under the person who runs it. What it may do is what that person delegated, intersected with what policy permits for the use case.

  • A human can delegate only what they hold
  • An agent never inherits its human's whole privilege set
  • Agent-to-agent messages are mediated and never delegate authority

Principles

Rules the code enforces, not promises.

  • Humans and agents are distinct principals.

    Agent tokens work only on agent routes, human tokens only on human routes.

  • Effective capability is delegated permitted.

    A human reaches nothing through an agent that policy denies them.

  • Deterministic first.

    The same request under the same conditions always gets the same answer.

  • AI analysis may only tighten.

    It can raise allow to approval or deny. No permit policy reads its output.

  • Approval binds to the exact request.

    Change one parameter and the approval no longer applies.

  • Every action leaves a trace.

    W3C trace context, one span per stage, append-only audit rows.
