# Route and role matrix

Status: v0, 2026-10-03, decision D9. Owner: security-architect. This file is the source security-tester
generates the negative test matrix from. A route the Gateway serves that is missing here is a defect.

## Principal kinds

| Kind | Token                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| A    | Agent: client-credentials token, `azp` is a registered agent client, `agent_id == azp`, lifetime at most 300 s            |
| H    | Human, browser: `azp` is `betsee-ecosystem` or `betsee-director`, `sub` is an active registered human                     |
| R    | Human via `betsee-demo-runner`, holding role `demo-initiator`. Demo-only: D7 allows session creation, D7a read-only GETs. |

Every route takes the token only from `Authorization: Bearer`. No cookie is accepted anywhere (D9).
Every token must satisfy all of the following:

- issuer `http://auth.betsee.localhost/realms/betsee`;
- audience `betsee-gateway`;
- RS256, signed by a key from the in-network JWKS;
- not expired.

Realm roles: `employee`, `approver`, `security-officer`, `org-admin`. "Org-wide" means the route
returns data across all sessions. **Own** means the data of sessions whose human is the caller.

## Status semantics

| Situation                                                                                            | Answer                                                                                                                       |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| No token; malformed, expired, wrong issuer, audience or algorithm; unknown key id; `agent_id != azp` | 401                                                                                                                          |
| Valid token of a principal kind the route does not accept, or a missing role                         | 403                                                                                                                          |
| Single object outside the caller's scope (another human's session or trace)                          | 404. Indistinguishable from a missing id.                                                                                    |
| Cedar decision on an action, including a foreign or unknown session id                               | 200 with `decision: deny`. A foreign or unknown session returns a plain deny with no human, use case or session fields (D9). |

## Regression tests owed for D9

1. A cookie alone, without a bearer token, on any route gives 401. A cross-site form post to
   `/approvals/{id}/approve` executes nothing.
2. A connector reporting a lower tier than the catalog label does not lower the taint. The next
   egress below the catalog tier is denied with CTL-TIER-002.
3. An allowed agent message raises the receiver's session taint to the sender's, and sets the
   receiver's untrusted-input flag.
4. A foreign session id and an unknown session id return byte-identical deny bodies, apart from
   `trace_id` and timestamps. Neither contains a human, use case or session field.
