# Betsee Design Contract

Owner: product-designer. Status: v0. Verifier: kierownik-session. Consumers: frontend-ecosystem
(`web/packages/ui`, `web/apps/ecosystem`), frontend-director (`web/apps/director`), identity-infra
(Keycloak login theme).

Files: this contract (the rules); `components.md` (component specs and icon ids); `tokens.json`
(source of truth); `tokens.css` and `tailwind-theme.css` generated by
`python3 docs/design/build-tokens.py` (`--check` in CI). **Must** and **never** are rules you raise
with product-designer before breaking; **should** is a default you may leave with a reason.

## 1. Visual principles

1. **Calm by default, loud for exceptions.** Most traffic is allowed, and allowed is green, so the
   brand colour stands for the healthy state. Only deny, waiting for a human, and quarantine pull
   the eye.
2. **The decision is the hero.** An action is never shown without its decision chip, and it always
   answers who, which agent, why, which capability, which resource, which policy.
3. **Deterministic first, AI second, visibly.** AI analysis appears after the deterministic verdict.
   It is a modifier that can only tighten, and it always carries the Gateway's `model_label`
   ("mock model (demo)", D2).
4. **Exact over persuasive.** Show what the Gateway received, not an agent's summary of it.
5. **One language, many products.** One token set and one shell. Products differ by name, mark,
   purpose line and layout archetype, never by colour: hue is reserved for decisions.

## 3. Stack rules

- **Tailwind v4**: `@import "tailwindcss";`, then `tokens.css`, then `tailwind-theme.css`. The theme
  resets Tailwind's default palette, type scale, radii, shadows and breakpoints, so only contract
  values exist: `bg-surface-1`, `text-fg-secondary`, `border-line-subtle`, `text-deny-fg`,
  `bg-approval-bg`, `rounded-lg`, `shadow-e1`, `font-mono`, `text-sm`. Spacing stays on the 4px
  Tailwind scale (`p-4` = 16px). Never raw hex, arbitrary colour values or inline styles for colour.
  Motion, layout and size tokens are used as `var(--bs-...)`.
- **Fonts**, bundled, never from a CDN: `@fontsource-variable/urbanist` (display),
  `@fontsource-variable/inter` (UI, the default sans), `@fontsource-variable/jetbrains-mono` (ids).
- **Motion** (`motion`, import from `motion/react`) for enter, exit and layout transitions (feed
  rows, drawers, the "n new" pill), with `useReducedMotion`. CSS keyframes for loops (live pulse,
  pending ring, edge flow through `stroke-dashoffset`). No other animation library.
- **Charts**: plain SVG components in `packages/ui` (bars, split bars, meters, sparklines). v0 needs
  no chart library. If a real time axis is needed, use uPlot, never a heavy library.
- **TanStack Query** maps onto states (section 11): `isPending` = skeleton; error with cached data =
  keep the data and mark it "as of"; error without data = error card; background refetch = no
  spinner. The SSE stream updates the query cache and does not drive its own rendering path.
- **Icons**: section 12.

## 4. Surfaces, spacing, radius, type

Dark only. Elevation comes from luminance steps plus a hairline, not from shadows.

| Level | Token / class                                               | Use                                                                  |
| ----- | ----------------------------------------------------------- | -------------------------------------------------------------------- |
| 0     | `bg-void`                                                   | behind the ecosystem app frame                                       |
| 1     | `bg-app`                                                    | page, Director canvas                                                |
| 2     | `bg-surface-1` + `shadow-e1`                                | cards, rails, panels                                                 |
| 3     | `bg-surface-2` (+ `shadow-e2` on hover)                     | hover, active nav item, selected row, tiles nested in a card         |
| 4     | `bg-surface-3`                                              | inputs, popovers, id tokens                                          |
| well  | `bg-surface-inset`                                          | meters, code, parameter blocks, waterfall lanes; never a nested tile |
| float | `bg-surface-overlay` + `backdrop-blur-[16px]` + `shadow-e3` | scenario dock, Director feed rail, popovers                          |

- **Spacing**: 4px base. Card padding 16 (Director) or 20 (ecosystem, KPI, approval). Grid gutter 20. In-row gaps 8-12.
- **Radius**: `pill` for chips, tabs and segmented controls; `xs` badges and id tokens; `sm` inputs and
  small buttons; `md` buttons and rows; `lg` cards and tiles; `xl` panels, rails and the app frame.
  Inner radius = outer radius - padding, minimum `xs`.
- **Type**: display (Urbanist) for page titles 28/600, KPI numbers 36/600 (Director 28) and the Home
  hero 48/600; UI (Inter) body 14 (the minimum for content on the demo projector), secondary 13,
  labels and chips 12/600, caps labels 11/600 tracked (rail groups, graph columns only); mono
  (JetBrains Mono) 13/500 for agent ids, capabilities, CTL ids, trace ids, policy ids, hashes and
  parameters. Agent ids are always mono; humans are always display names. Aligned numbers use
  `tabular-nums`.
- **Controls**: 28 / 36 (default) / 44 (hero actions, Approve). One primary button per view, filled
  `bg-accent` with `text-fg-on-accent` (white on accent fails contrast).

## 5. Colour and severity

| Meaning             | Label                                       | Tokens                             | Icon                                  |
| ------------------- | ------------------------------------------- | ---------------------------------- | ------------------------------------- |
| `allow`             | Allowed                                     | `allow-*`                          | `streamline:check`                    |
| `deny`              | Denied                                      | `deny-*`; rows get a 2px left bar  | `streamline-flex:block-2`             |
| `require_approval`  | Awaiting approval, then Approved / Rejected | `approval-*`, dashed while pending | `streamline-flex:hourglass`           |
| `require_step_up`   | Awaiting step-up, then Verified / Failed    | `stepup-*`, dashed while pending   | `streamline-flex:fingerprint-1`       |
| AI-tightened        | modifier "AI-tightened", never alone        | `tightened-*`                      | `streamline:ai-chip-spark`            |
| quarantined (agent) | Quarantined                                 | `quarantined-*` + 135deg hatch     | `streamline-flex:padlock-square-1`    |
| suspended (agent)   | Suspended                                   | `suspended-*` + neutral hatch      | `streamline-flex:button-pause-circle` |

- Approved and Verified use allow styling; Rejected and Failed use deny styling.
- Quarantine orange is not deny red on purpose: it is a state of a principal, not a verdict on an
  action.
- **SecurityEvent severity** uses `SeverityBadge`, a square-cornered badge (`rounded-xs`, never a
  pill, so it never reads as a decision) with an 8px square marker + word: info (`fg-secondary`), low
  (`viz-neutral-1`), medium (`approval-fg`), high (`quarantined-fg`), critical (`deny-fg`). Value
  names follow `contracts/events.md`.
- **Information tier carries no hue**: a 4-step level meter + word (TierBadge). When a tier causes a
  deny, the tier stage of the trace turns red, not the badge.
- System status (connection, errors) uses `danger` / `warning` / `info` only in the top bar,
  banners and error cards, never in a chip.
- **Colour is never the only carrier**: every decision, state and severity shows icon or marker plus
  word. Red and green are close for deuteranopes.
- **Glow** (`shadow-live`, `accent-glow`, `accent-edge`) means live or flowing: the live dot, live
  edges, an agent mark at the moment it acts. Never decorative, never on buttons, never red.
- `gradient.feature` fills at most one surface per view (the feature KPI tile, the running act).

## 6. Layout and density

**Ecosystem** (`betsee.localhost`): an app frame (`bg-app`, `rounded-xl`, 12px inset from the
viewport at >= 1280px, flush below) holding a 248px labelled rail (72px collapsed below 1280px)
and a 64px top bar (search with Cmd K, stream status, notifications, human). Content: 32px padding,
max 1440, 12 columns, gutter 20. Page header: lockup, title, purpose line, actions right. Product
sub-navigation is a pill tab bar under the header. Patterns: KPI row (4 tiles x 3 cols, the first
may be the feature tile); main + aside (8/4); list + detail (5/7, detail sticky); card grid.

**Home**: hero "See every agent." with the tagline; KPI row (Agents active [feature], Actions in
15 min, Denied, Awaiting human); Gateway pipeline health (15 stages with counts) + recent security
events; six product tiles (mark, name, purpose line, one live number; Director opens its host).

**Director** (`director.betsee.localhost`, structure from frontend-director's IA): full-bleed, no
frame. 64px icon rail (Live, Graph, Coverage; ecosystem link at the bottom), 56px top bar
(organization, stream status, "Awaiting human" count linking to Approvals, MockBadge in mock builds,
human), content on `bg-app` with the 20px dot grid, a 384px live feed rail floating on
`surface-overlay` at the right, and the scenario dock floating bottom-centre. Agent drawer and span
detail: 480px from the right. Trace explorer: decision sentence (display 18), the seven question
cells (4 + 3 grid), pipeline rail, waterfall, then composition and span detail side by side.
Breakpoints: >= 1440 as described; 1280-1439 feed 320; 1024-1279 feed becomes a toggled overlay;
below 1024 a notice "The Director needs a screen at least 1024px wide." Verify at 1920x1080 and
1440x900. **The whole demo population (5 agents) is visible on Live without scrolling at both
sizes**: team groups flow side by side in a wrapping row (each with its caps label), not one group
per row.

**Density**: the ecosystem is comfortable (rows 48, card padding 20, one question per card). The
Director is compact (rows 36-40, padding 12-16, secondary text 13) because watching many agents at
once is its job; it still never drops below 12px text or 24px hit targets. A dashboard card answers
one question and its title says which. At most 4 KPI tiles per row.

## 7. Navigation

- Ecosystem rail: PRODUCTS (Home, Approvals with a pending count, Policy Studio, Identity, Connect),
  LIVE (Director, with `streamline-flex:arrow-expand` to show that it opens the other host). Gateway
  has no rail entry.
- Routes: `/approvals` (Pending, Decided); `/policy-studio/controls | policies | use-cases`;
  `/identity/agents | humans | teams`; `/connect/connectors | tools | models`; details append `/:id`.
  Director routes per its IA: `/`, `/traces/:traceId`, `/agents/:agentId`, `/graph`, `/coverage`.
- Cross-host links are absolute and open in the same tab (Keycloak SSO keeps the session): trace id
  -> Director trace; "Awaiting human" and the approval stage -> `/approvals`; policy id -> Policy
  Studio; agent "Edit delegation" -> Identity; CTL id -> the control in Policy Studio.
- Every id token with a detail page is a link.

## 8. Animation philosophy

Motion tells you something happened or is still happening. It never decorates and never makes a
security fact look uncertain. Durations and easings come from `motion.*` tokens.

Animates: hover/press colour (`instant`); the live dot and pending chips or stages (slow pulse, the
only loops); a new feed row (fade + 8px, `base`); the newest decision tick; an edge or pipeline line
on an event (one pass, `edge-flow`); an agent mark when it acts (one glow, 600ms); an agent becoming
quarantined (one ring, then a static hatch); a resolved pending row (one 600ms tint); drawers
(`slow` in, `base` out); skeleton shimmer.

Never animates: a decision chip changing value (it swaps instantly); numbers (no count-up on KPIs,
budgets, evidence or money); red (no shake, bounce, blink or loop); layout under the pointer (while
the pointer is over the feed or the feed is scrolled, new rows queue behind an "n new" pill); page
and product switches; parallax or 3D tilt; charts drawing in on load. `prefers-reduced-motion`
removes translate, pulse, flow and rings; fades stay at 120ms or less.

## 9. Graph style

Node canvas, not a force layout: fixed columns computed from data (Humans | Agents by team | Tools
and connectors) on `bg-app` with the dot grid. Nodes are `surface-1` cards with a mark, a mono name
and ports on both sides; humans are circles, agents rounded squares, everywhere. Edges are
horizontal-tangent beziers coloured by their latest decision (allow is translucent accent, deny
solid red, pending dashed), labelled with small pills ("denied", "breaker open", "x24"). One light
pulse travels an edge per event. The pipeline rail in the trace explorer uses the same node and edge
language in one row. Specs: `components.md`, GraphCanvas and PipelineRail.

## 10. Component patterns

Shared primitives in `packages/ui`, Director-only components in `apps/director` (the split and
specs are in `components.md`): DecisionChip, AgentTile, PipelineRail + SpanRow, ControlCard,
CapabilityIntersection, ApprovalCard, plus StreamStatus, MockBadge, LifecycleBadge, TierBadge,
SeverityBadge, IdToken, KpiTile, FeedRow, ScenarioDock, GraphCanvas, coverage row. Rules that hold
across them:

- Humans: circle with initials. Agents: rounded square with `streamline-flex:ai-chip-robot`.
- Every action row carries a DecisionChip; every AI verdict carries a MockBadge with `model_label`.
- Approval cards lead with the parameters the Gateway received; there is never an approve-all, an
  approve shortcut or an approve button without those parameters on screen.
- A new pattern, a material navigation change, a major new page, a core interaction change or a rule
  break goes to product-designer first. Everything else, build to this contract without asking.

## 11. Empty, loading, error

- **Loading**: a skeleton in the final layout (`surface-2` blocks with the component's radius),
  shown after 150ms. No page spinners; a 14px spinner only inside a pressed button.
- **Empty**: centred in its card: a 48px `surface-2` tile with a 28px glyph in `fg-tertiary`, a
  14/600 title, one sentence naming the next step, at most one secondary button. "No agent has
  acted yet. Launch Act 1." / "No agents registered. Run scripts/bootstrap." / "Nothing is waiting
  for a human."
- **Error**: `streamline-flex:warning-diamond` in `danger`, a title ("Could not load traces"), a
  mono detail line ("HTTP 503 from the Gateway - trace 4bf92f35"), Retry. Keep data already shown
  and mark it "as of 21:04:12". No stack traces; never blame the user.
- **Offline**: a banner at the top of the content with a 2px `danger` left bar: "Gateway
  unreachable. Showing data as of 21:04:12." + Retry.
- **Forbidden**: full page with the lockup and the roles needed.

## 12. Icons

- **Streamline Flex, line** (D3) through Iconify set `streamline-flex`, base names only. The free
  Flex set on Iconify has 500 glyphs and lacks some interface primitives (plus, close, chevrons,
  check, copy, eye); take those from the sibling set `streamline`, short names only. Both draw on a
  14px grid with a 1px round stroke. Never `-solid` or `-remix`, never another library, never emoji.
- **Offline**: `@iconify-json/streamline-flex` and `@iconify-json/streamline` at build time. One
  `Icon` component in `packages/ui` renders from a generated subset of the ids in `components.md`.
  `@iconify/react` fetches from `api.iconify.design` by default and must not: register the subset
  with `addCollection`, or render the SVG body directly. The stack must run without a network.
- Sizes 14 (chips, dense rows), 16 (default), 20 (rails), 28 (marks, empty states). `currentColor`
  always. Icon-only buttons have `aria-label` and a tooltip.
- Licence CC BY 4.0: credit "Icons by Streamline (streamlinehq.com), CC BY 4.0" in the README and
  the ecosystem footer.

## 13. Copy

- Lines: tagline "Better see what your agents do."; core message "See every agent." (Home hero and
  the close); principle "Nondeterministic agents operate inside deterministic execution boundaries."
- Voice: calm, exact, present tense, the principal as subject: "invoice-assistant asked for
  payments.transfer. Awaiting approval."
- Explain a decision with "because" and the control: "Denied because CTL-007 Information tier
  ceiling: the resource is restricted, the session ceiling is internal."
- The shared vocabulary from the charter, exactly. Analyzer copy: "AI analysis" + the model label;
  "the analyzer flagged instructions inside data". Never present the mock as a real model.
- Never: "AI firewall", "prompt injection filter", "magic", "smart", "AI-powered" as a claim,
  "hacker", fear language, exclamation marks, emoji.
- Numbers: thousands separators, ISO currency after the amount ("48,000.00 EUR"), 24h times,
  relative times with the absolute time in a tooltip. Buttons are verbs: Approve, Reject, Launch
  Act 3, Reset scenario, Release agent, Retry.

## 14. Accessibility and verification

- Contrast on `surface-1`: primary 16.2, secondary 7.7, tertiary 4.8; decision
  foregrounds 5.5 (deny) to 10.0 (approval). Focus: a 2px `line-focus` ring with a 2px offset,
  never removed. Feed rows, tiles, stages and span rows are keyboard reachable; Esc closes drawers.
  The feed announces summaries ("3 new actions, 1 denied") through a polite live region.
- F15/F16 verification checks: tokens only, decisions per section 5, MockBadge wherever AI analysis
  or fixtures appear, the never list in section 8, layout at 1920x1080 and 1440x900, empty/loading/
  error per view, forbidden words absent, Streamline icons loaded offline.
